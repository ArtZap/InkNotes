# InkNotes: конкуренты, что добавить, как автоматически проверять формулы

Дата: 14.11.2026. Основа: STATUS.md (v0.38), код репозитория ArtZap/InkNotes (ветка main), поиск по конкурентам и по литературе. Что я проверил сам, а что предположил, помечено в тексте.

## 1. Главное

1. Приложение уже богаче, чем у большинства конкурентов на Android. Разрыв остался в четырёх местах: ответ формулы «вашим почерком» и интерактивные переменные (Apple), ИИ для учёбы (Goodnotes, MyScript), расшифровка лекций (Samsung, Notability), открытый формат вывода (Markdown/Obsidian, WebDAV).
2. **В автотестах формул есть слепое пятно.** `FormulaBench` читает формулы через `PerfectReader`, то есть подставляет правильные символы. Он проверяет раскладку (дроби, степени, корни) и вычисление, но **не проверяет, как ML Kit читает цифры и буквы**. А это самое слабое звено: символы читает ML Kit с английской моделью, раскладку считает ваш код. Реальное чтение проверяется только двумя страницами (`RealPagesTest`) и отчётами «Неверно…».
3. Тестировать без человека можно, и ответ почти бесплатный: у математики есть оракул. Случайное выражение, для которого `Calc` считает точный ответ, превращается в «рукописный» штрих-ввод, проходит весь конвейер, и ответы сравниваются. Плюс метаморфические тесты (масштаб, поворот, шум не должны менять ответ) и замер ML Kit на размеченных символах CROHME. Схема в разделе 3.
4. Для «самого крутого» главная метрика — **доля неверных ответов, а не верных**. Неверный ответ вредит больше, чем отсутствие ответа. Показывать ответ только когда два лучших варианта чтения дают одно и то же, остальное помечать «не уверен».

## 3. Как проверять распознавание формул без человека

Принцип: чем выше уровень, тем ближе к реальности, но тем дороже и менее точна диагностика. Нужны все уровни, каждый со своим порогом в CI (как уже сделано в `formula-baseline.json`).

### Уровень 0 (нового нет, главная дыра): чтение символов ML Kit

- Берём размеченные группы штрихов из CROHME (там метки по символам, ваш `InkMl` их уже читает), подаём в `MathNotes.reader` на эмуляторе, сравниваем с меткой.
- Выход: точность по классам, матрица ошибок (топ-20 путаниц: `1/7`, `x/×`, `2/z`, `-/черта дроби`, `u/v`), **полнота n-best** (есть ли верный вариант среди 3–5 лучших). Эта цифра — потолок того, что даст перевыбор варианта по грамматике.
- Запуск: `androidTest` на эмуляторе CI с образом Google APIs; модель ML Kit кэшировать между прогонами. Ваш STATUS отмечает редкие SIGSEGV эмулятора в скриншот-тестах, поэтому вынести в отдельную задачу с одним повтором.
- Порог: падение точности > 1 п.п. или рост неверных > 0,5 п.п., как в `regressions()`.

### Уровень 1 (есть): раскладка с идеальным читателем
Оставить как есть. Добавить наборы CROHME 2014/2016/2019, сейчас в базовой линии только 2013.

### Уровень 2: весь конвейер на реальном почерке
ML Kit + раскладка + разбор + вычисление на CROHME 2014–2019 и выборке MathWriting (≈2000 формул, 230 тыс. рукописных образцов в наборе, лицензия CC BY-NC-SA). Сравнение по значению, как у вас в `same()`, плюс для диагностики: доля точных совпадений, «не больше 1 ошибки», символьная ошибка по LaTeX.

### Уровень 3 (новый, главное): синтетика с оракулом

1. **Генератор выражений** по грамматике (арифметика, дроби, степени, корни, функции, скобки, интегралы с известной первообразной, единицы). Верный ответ даёт `Calc.evaluate`, он уже покрыт `CalcTest`, то есть от почерка не зависит.
2. **Рендер «рукописью».** Банк глифов: реальные штрихи символов из CROHME/MathWriting (и позже ваши собственные). Позиции и размеры берём из `Typeset.kt` (он уже знает, где каждый символ стоит в печатной формуле). Искажения: дрожание базовой линии ±, масштаб символа ±15 %, поворот ±8°, наклон ±12°, шум точек, прореживание, зазоры, порядок штрихов.
3. **Прогон** через уровень 2, сравнение с оракулом.
4. **Калибровка.** Сравнить точность синтетики с точностью на реальном CROHME. Если расхождение держится в пределах нескольких пунктов, синтетике можно верить и ею охотиться на конкретные проблемы (например, 10 тыс. примеров, где рядом цифры `1`, `7`, `l`, `/`).
5. Ограничение: синтетика не заменяет реальный почерк. Это дешёвый поиск регрессий и «опасных» мест, а не оценка качества для публикации.

### Уровень 4: метаморфические тесты (не нужны метки)
Любая страница (CROHME, ваши страницы, синтетика) проходит преобразования, после которых ответ не должен меняться: масштаб ×0,5…×3, сдвиг, поворот ±3–5°, наклон, шум в точках, ресэмплинг ×2 и ÷2, дробление штриха на два, перемешивание порядка штрихов. Отчёт: доля «перевернувшихся» ответов по каждому преобразованию. Раскладку можно гонять на JVM с `PerfectReader` (быстро, в CI всегда), ML Kit-вариант на эмуляторе по ночам. Заодно проверяется «поворот страницы», на котором раскладка по базовой линии, скорее всего, ломается (гипотеза, не проверял).

### Уровень 5 (есть): страницы с планшета
`MathReportTest` оставить. Добавить скрипт `tools/promote-report.sh`, который кладёт свежий `math-report-*.json` в ресурсы и проверяет формат. Каждая ошибка с планшета становится постоянным тестом.

### Уровень 6 (по желанию): метки от модели с глазами
Для страниц вашего почерка без меток: Claude читает изображение и выдаёт LaTeX, пользуемся только теми, где он совпал с ML Kit или с оракулом; расхождения (≈5 %) смотрите вы. Это разовая работа на вашем компьютере. Рукопись при этом покидает устройство, поэтому только для ваших собственных страниц.

### Метрики
- Главная: **доля неверных ответов** среди показанных (цель ≤ 2 %), рядом доля верных и доля «нет ответа».
- Диагностика: точность символов, полнота n-best, точные совпадения LaTeX, символьная ошибка.
- Для сравнения с литературой: в статье MathWriting у Transformer на тесте символьная ошибка 5,56 %, у Google Document AI на картинках 7,17 %. Для CROHME принято считать долю точных совпадений; визуальную метрику CDM предлагают взамен, потому что точное совпадение штрафует равнозначные записи одной формулы.
- Доверительные интервалы (бутстрап) в отчёте, иначе колебания на 200 примерах принимаются за прогресс.

## 4. Как улучшить само распознавание (по убыванию отдачи к цене)

1. **Сначала замер (уровень 0).** Без него все правки наугад.
2. **Перевыбор по n-best + грамматика.** Брать несколько вариантов ML Kit на группу символов и выбирать комбинацию, которая разбирается, имеет сбалансированные скобки, не ставит два оператора подряд, не даёт деления на ноль. В `MathPage.read` есть режим `Prefer.FIRST`; насколько уже используется перевыбор, не смотрел.
3. **Уверенность и воздержание.** Если ответ меняется при втором варианте, показывать ответ с пометкой «?» и вариантами. Конкуренты так не делают.
4. **Личная адаптация.** Каждая правка из «Неверно…» пополняет вашу матрицу путаниц (ваши `1/7`, `u/v`), и она сдвигает приоритеты перевыбора. Работает на устройстве, один пользователь, поэтому даёт много при малой цене.
5. **Свой читатель символов.** Небольшая сеть по штрихам (LiteRT/TFLite, 100–500 КБ), обучена на CROHME + MathWriting + ваших образцах, работает вторым голосом рядом с ML Kit и закрывает то, чего нет в английской модели (греческие, ∑, ∫, √, ≤, ∞). Делать только если уровень 0 покажет слабые классы. **Осторожно с лицензией:** CROHME и MathWriting под CC BY-NC-SA, то есть модель, обученная на них, для личного использования подходит, а при публикации в Google Play нужно отдельно разбираться.
6. **Целая модель формулы вместо раскладки не рекомендуется:** открытые веса, которые я нашёл, работают по картинке, тяжёлые, а одна из них (TrOCR на MathWriting) даёт символьную ошибку 14,9 % по описанию автора. Годятся максимум как инструмент разметки в лаборатории.

## 5. Что реализовать (идеи по приоритету)

Размер: S до 2–3 дней, M до недели, L больше.

**Формулы (на чём вы можете быть лучше Apple)**
- (M) Ответ вашим почерком: банк глифов собирается из ваших цифр, он же нужен для уровня 3. Один труд на две цели.
- (M) Бегунки переменных: потянуть число, график и ответы ниже пересчитываются.
- (S) «Добавить к графику» и несколько функций на одной оси, если этого ещё нет.
- (M) Проверка покрытия: матрицы, системы, суммы, пределы. Отчёт покрытия у бенча уже есть (181 формула на раскладке), смотрите долю формул, которые InkNotes «не умеет представить».
- (S) Показ «как прочитано»: печатный вид под рукописью, тап по символу, исправить.

**Учёба**
- (M) Вопросы и резюме конспекта через API с вашим ключом (в списке расширений уже есть). Тесты верно/неверно и с выбором ответа — как у MyScript 7.4.
- (M) Расшифровка лекции с привязкой к штрихам: распознавание речи на устройстве, текст попадает в поиск. Запись с привязкой к штрихам уже есть.
- (M) Проверка орфографии рукописи **на русском**: у Goodnotes её нет (там EN, ES, DE, NL), у вас может быть.

**Почерк**
- (M) Лассо → «Выровнять почерк»: строка выравнивается по базовой линии, интервалы нормализуются, форма штрихов не меняется (как у Apple и Samsung).
- (M) Личный словарь для поиска и распознавания: ваши термины и сокращения.

**Данные**
- (M) Экспорт в Markdown для Obsidian: страницы как картинки, распознанный текст, формулы как LaTeX. Подходит к вашему Second Brain, особенно с автокопией.
- (M) WebDAV на уже сделанной логике Google Диска (Яндекс Диск, Nextcloud).
- (L) Просмотр тетради в браузере (только чтение) для телефона и ноутбука; Goodnotes уже на Android, Windows и в вебе, так что без этого вы проигрываете по доступности.

**Красота и ощущение** (по коду вижу стили «Классический» и «Премиум», тему «Mystic»; скриншотов не видел, поэтому конкретику ниже считайте гипотезами)
- (M) Единые токены дизайна (цвета, отступы, радиусы, тени), чтобы все диалоги выглядели из одного набора.
- (M) Переходы: обложка тетради раскрывается в страницу (общий элемент), листание страниц с инерцией на 144 Гц.
- (S) Тактильный отклик на переключение инструментов и на ластик.
- (M) Адаптивная раскладка планшета: библиотека + миниатюры + страница в трёх колонках в альбомной ориентации.
- (M) Виджеты и плитка быстрой заметки в стиле темы.
- (L) Доступность (TalkBack), локализация, скриншоты для магазина: нужны, только если публикуете.

## 6. План работ

1. **Неделя 1. Измерение.** Уровень 0 (чтение символов ML Kit) + матрица ошибок + n-best; расширить бенч на CROHME 2014–2019; метаморфические тесты раскладки на JVM. Результат: цифры «где мы сейчас» и первая версия базовой линии.
2. **Неделя 2. Синтетика.** Генератор выражений, банк глифов, рендер, калибровка по CROHME. Ночной прогон в CI.
3. **Неделя 3. Улучшения по данным.** Перевыбор по n-best, воздержание при сомнении, личная матрица путаниц. После каждого шага смотрим долю неверных.
4. **Дальше по очереди:** ответ почерком + бегунки; экспорт в Obsidian; вопросы по конспекту; расшифровка лекций; WebDAV.
