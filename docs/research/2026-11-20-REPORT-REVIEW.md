## Что в отчёте неточно или устарело

- «Перебор при ошибке срабатывает только на единицах» — неверно: для «выражение =» берётся любой `MathError` из `Calc.evaluate`. Пробел есть, но другой: нет такого перебора для уравнений, определений и графиков.
- Причина чувствительности к повороту — полоса `side()`: не доказано. Метаморфика меряет раскладку; FORMULAS.md объясняет разрыв штриха оценкой высоты строки. «Выпрямление строки целиком» уже пробовали — на данных хуже.
- «Проверить кратные корни» — уже сделано: `Solver` ищет касающиеся корни (минимум |f| без смены знака).
- `lg₂ 16` — уже записано в STATUS как известная ошибка.
- EMNIST «Public Domain / CC0» — не подтверждено: явной лицензии на страницах NIST и Western Sydney не нашёл. Перед использованием в APK проверить отдельно. Кроме того, EMNIST — сканы бумажных бланков, без математических знаков.

## Уровень 3 отчёта и решения владельца

Решения владельца (14.11, уточнено 20.11):
- NC-данные (CROHME, MathWriting) — только в тестах, не в APK; своя модель — на разрешённых данных или образцах пользователя.
- Облачные нейросети не используем: платить за доступ владелец не хочет, сервера нет.

Пункты «своя большая модель формул — не делать» и «MyScript — не делать» в ROADMAP и плане 14.11 были рекомендациями составителя плана, а не решениями владельца (ROADMAP исправлен 20.11).

- 3A, своя E2E-модель формул на синтетике и разрешённых данных — **разрешена**. Отложена по объёму работ и риску (модель только на синтетике обычно хуже на живом почерке): делать, если после пунктов 1–8 ниже раскладка останется главным источником ошибок.
- 3B, MyScript SDK — по лицензиям подходит, но платный; условия для Android не запрошены. Решение за владельцем.
- 3C, облачный fallback (Gemini/GPT/Mathpix) — **не берём** (решение владельца: платный доступ, нет сервера).

## Что берём (по отдаче на единицу работы)

**Сразу, S, проверка — FormulaBench + RealPagesTest + SymbolReadTest:**
1. Мягкие альтернативы для знаков раскладки.
2. `Voices`/`Learned` при несовпадении числа токенов: не выключаться; чтение по глифам (как `Correct.side`).
3. `Prefer.SURFACE` для `z = …`.
4. Эксперимент на `SymbolReadTest`: (а) штрихи от угла `WritingArea`; (б) паузы внутри глифа и между глифами; (в) контекст по роли дыры. Берём только то, что улучшит стенд.

**Следом, M:**
5. Поиск лучших комбинаций по стоимости (ранг ML Kit + расхождение двух прочтений + голос образцов + согласие с переменными страницы) вместо «≤2 изменения, 40 штук». Регрессию держит `formula-outcomes.tsv`.
6. Перебор по смыслу для уравнений и определений: лишнее неизвестное или ошибка решателя → следующее прочтение, ответ «под вопросом».
7. `Samples`: не зависеть от порядка штрихов ($P point-cloud и/или растр 16×16), проверка `SamplesBenchTest`.

**Позже, по стенду:**
8. Свой маленький классификатор символов на разрешённых данных или образцах пользователя. Начинать с образцов пользователя (растр + эмбеддинги); EMNIST — только после проверки лицензии; синтетика из OFL-шрифтов (STIX, Latin Modern, Noto Math) — для знаков, которых нет в рукописных наборах.
9. Своя E2E-модель формул (3A) — если после 1–8 раскладка всё ещё главная беда.

## Что сделано в 0.62 (20.11)

- Пункт 1: альтернативы только для `′` → `^{1}` и `°` → `^{0}` (они стоят высоко справа, значит как цифра — показатель). `+` → `t` **не включён**: с ним 87 формул CROHME без ответа стали неверными — повисший из-за сломанной раскладки «1+» начинал разбираться. Точка-умножение не трогается (0.41, x = −2,5). Всё с `′` и `°` разбирается и так, поэтому альтернатива работает только там, где страница перебирает прочтения после ошибки вычисления.
- Пункт 2: `Learned.adjust` и `Voices.adjust` берут первое прочтение с нужным числом символов; `GlyphReading.extend` — при неверном числе символов глифы (2–4) читаются по одному, склейка идёт вторым вариантом.
- Пункт 3: `Prefer.SURFACE` — прочтения с x и y.
- Пункт 4: (а) «от угла» и (б) паузы по глифам — за переключателями `ReadOptions`, сравниваются на эмуляторе (`SymbolReadTest`, `FormulaReadTest`) в одном прогоне. (в) контекст по роли дыры не сделан: `RunReader.read` не знает уровня дыры, нужна смена интерфейса — отдельно, если (а)/(б) что-то дадут.
- Стенд CROHME на JVM (идеальные символы): исходы всех формул как в 0.61.

## 0.63: пункт 5 — выбор среди вариантов (20.11)

- Сначала стенд эмулятора сделан повторяемым на JVM (записанные прочтения ML Kit), иначе подбор шёл бы вслепую по 15 минут CI на попытку.

- Дало: «1» первой для одиночных l/I (+8 −1) и цена символов (+5, без потерь). Эмулятор: неверных среди показанных 55,0 % → 49,3 %, символ первым 76,9 % → 80,7 %.
- Из оставшихся неверных половина — раскладка, четверть — верного варианта нет у ML Kit. Дальше: пункт 6 (перебор по смыслу для уравнений) и 7–8 (свои образцы, свой классификатор символов) — для «нет у ML Kit»; раскладка — отдельно.
