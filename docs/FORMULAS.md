# Формулы: как устроено, что измерено, что пробовали

На 15.11.2026, версия 0.43.

## Конвейер

```
штрихи страницы
  └─ MathPage.analyze         найти «=» (findEquals), стороны (side), строки
       ├─ MathLayout.formula  раскладка: штрихи → глифы (items/join) → структура
       │                      (дроби, корни, степени, индексы, скобки) → Piece.Text / Piece.Hole
       ├─ RunReader.read      ML Kit читает каждую «дыру» (ряд глифов одного уровня) как текст,
       │                      MathNotes: 5 вариантов дважды (без контекста и с "12+3*4 = ")
       ├─ readings            комбинации вариантов → текст → Parser → Expr, с порядком по Prefer
       │                      (FIRST, NUMBERS — меньше букв, LETTERS — системы, GRAPH — y = f(x))
       └─ Calc                evaluate / solve / graph / surface, Env — определения выше по странице
PageAnswer                    ответ, «под вопросом» (others), метка missing, fix (для исправления)
```

- **`MathLayout`** — геометрия. Пороги лежат в `Tune` (поля `@JvmField var`), подбираются `LayoutTuner` на CROHME 2013 обучающей. Для проверки есть 2013 тестовая и 2012.
  - `Shift` — 8 сдвигов порогов. Если со сдвигом ответ другой, ответ «под вопросом».
  - `Piece.Hole` хранит глифы и уровень, `Piece.Text` для знаков по форме (+, −, ·, °, ′) — их штрихи. Это нужно окну исправления.
  - Точка над короткой палочкой склеивается с ней (`iDot`, i жирным пером).
- **`MathPage`** — страница целиком.
  - Строки и стороны: `side()`. Штрихи, которые ближе к соседней строке с «=», не берутся.
  - Определения (`a = 5`, `f(x) = …`, `y = …` — график, `z = …` — поверхность); системы и неравенства.
  - «Выражение =», «x =» под уравнением.
  - **Закрепления** (`pinned`): текст формулы, заданный пользователем, по отпечатку штрихов (`Correct.fingerprint`) берётся вместо чтения.
  - **Метки** `missing`: после «=» ничего не вышло, или у y = / z = нет графика.
  - Если прочтение падает на единицах (буква принята за единицу: g — грамм/ускорение, B — вольт), берётся прочтение, которое считается. Ответ при этом «под вопросом», ошибка — второй вариант.
- **`MathNotes`** (Android) — ML Kit, кеш прочтений, `Doubt` (два прочтения ML Kit расходятся → `sure = false`), `prepare(fix)` для окна, `FixStore`, подмена по выученному почерку (`Learned.adjust`).
- **`Correct`** (чистый Kotlin) — модель окна исправления:
  - `side()` разбирает формулу по символам: у каждого символа кандидаты, уровень, «не уверен»; стартовый выбор — тот, что дал ответ страницы.
  - `text()` собирает текст обратно с выбранными символами и местами (`LINE`, `UP`, `DOWN`, `OFF` = убран).
  - `outcome()` отвечает, как страница: значение, корни, график, поверхность или почему нет.
  - `Learned` — счётчики «прочитано X → выбрано Y».
- **`FixStore`** — `filesDir`:
  - `formula-pins.tsv` — закрепления, до 5000, вытесняются по LRU;
  - `formula-learned.tsv` — выученные замены;
  - `formula-settings.txt` — «учиться», «спрашивать».

## Что измерено (0.42–0.43)

**Стенд CROHME на JVM** (`FormulaBench`, `PerfectReader` подставляет верные символы, то есть меряется раскладка и разбор):
- CROHME 2013 тест, чтение формулы: неверных 22,7 % (0.40) → 14,4 % (0.41) → меньше в 0.42.
- CROHME 2012, на котором пороги не подбирались: 15,4 % → 11,4 %.
- Исход каждой формулы хранится в `app/src/test/resources/formula-outcomes.tsv`. Регрессия — это когда больше формул стали неверными, чем перестали. Плюс кривая «риск — покрытие».

**Метаморфика** (`MetamorphicTest`):
- Масштаб, сдвиг и порядок штрихов ответ не меняют.
- Поворот на ±4° меняет ответ у 14–16 % формул, наклон на 10° — у 11 %, разрыв одного штриха — у 27 % (высота строки оценивается по штрихам).
- `BoundaryTest`: при подъёме символа ответ идёт по порядку индекс → рядом → степень.

**Настоящий ML Kit на эмуляторе** (`formulas-device.yml`, 304 формулы CROHME 2013 тест и 2012):
- Отдельные символы: верный первым — 77 %, среди вариантов — 96 %.
  - Частые путаницы: 1 → l/I, 0 → o, q → 9, π → T, n → m/h.
  - Знаки + ( √ ∫ раскладка определяет сама по форме.
  - **Оценок кандидатов эта модель ML Kit не даёт.**
- Выделенная формула: неверных среди показанных 57 %; с идеальными символами было 17 %.
- «Выражение =» на странице:
  - неверных от всех ответов 27,8 % → 18,1 % после сомнения ML Kit;
  - среди уверенно показанных 38,5 % → 32,5 %.

**Вывод:** раскладка уже не главное. Беда — чтение символов, особенно в формулах из букв. Отсюда окно исправления и учёба на почерке пользователя, а не новые пороги.

## Повтор чтений ML Kit на JVM (0.63)

- На эмуляторе `FormulaReadTest` записывает всё, что прочёл ML Kit (оба прохода), в `reads.tsv`; workflow печатает его в лог (gzip + base64). Запись лежит в `app/src/test/resources/replay-reads.tsv.gz`.
- `ReplayBenchTest` читает те же формулы CROHME с этими прочтениями (`RecordedReader`) и сходится с эмулятором (неверных среди показанных 55,2 % у обоих; на странице ±1 формула). Секунды вместо прогона CI. Держит регрессию по `replay-outcomes.tsv`, как `FormulaBenchTest` по раскладке.
- Обновить запись: из лога «Formulas on a device» (между `== reads.tsv.gz.b64 begin/end`) → base64 -d → `replay-reads.tsv.gz`. Ключ — «набор/имя» и номера штрихов.

Что показал повтор (1177 прочтений дыр, 298 формул):
- верное прочтение первым в 74 %, среди вариантов — в 91 %; вторым — в 8 %;
- одиночная палочка, прочитанная как `l`, — это 1 в 47 случаях из 51, как `I` — в 33 из 38 (0.63: «1» пробуется первой, если буквы нет на странице);
- при расхождении двух проходов первый вариант «после арифметики» верен в 30 %, «как есть» — в 12 %; но на формулах это ничего не дало (выделенные без изменений, страница −1), не включено;
- из 110 неверных: 51 — раскладка (с идеальными символами тоже неверно), 29 — верного варианта нет среди 10, 30 — выбор;
- порядок перебора комбинаций (по месту в списках, до 200) ничего не меняет: решает, что стоит первым в каждой дыре;
- цена символов (`ReadOptions.cost`: место в списке ML Kit · 0,7 + насколько символ необычен в формуле): +5 формул, без потерь; плато 0,6–0,9.

## Что пробовали и не включили (хуже на данных)

- Выпрямление строки целиком перед раскладкой.
- Склейка продолженного штриха: склеивала индекс с буквой.
- Десятичная точка только у самой линии.
- Высота строки по глифам вместо штрихов.
- Согласие первых двух прочтений ML Kit как сигнал сомнения: помечает 97 % ответов.
- `+` как запасное `t` (0.62): повисший «1+» начинал разбираться, 87 формул без ответа стали неверными.
- Подача штрихов в ML Kit от угла области и паузы по глифам (0.62): ML Kit безразличен, «от угла» на одну формулу хуже.
- Перебор комбинаций по месту в списках вместо «по дырам», до 200 комбинаций (0.63): без изменений.
- Голос образцов без зависимости от порядка штрихов (20.11, `SamplesBenchTest`, 1271 символ CROHME): облако точек ($P) при той же точности ~97 % уверено в 14 % символов против 23–28 % у пути; «ближайшее из двух» — так же; путь плюс обратный порядок и направление — +1 пункт охвата, в пределах шума. Порядок и направление штрихов — признак, а не помеха.
- Согласие букв между дырами формулы (вариант с буквой, прочитанной в других дырах, — выше): при скидке ≥ 1,5 места −6…−11 верных против +1 (в a + b буква a вытесняет b).
- «Точка ниже середины между цифрами — десятичная» для русской рукописи: ломала x = −2,5 на страницах владельца. Оставлено только для английской рукописи.

| `ReplayBenchTest` (JVM) | Стенд эмулятора на записанных прочтениях ML Kit, регрессия по `replay-outcomes.tsv` |
| `tools/formula-bench.sh` | Данные CROHME (кеш, проверка хэша), `--update` — новая базовая линия (только при намеренном изменении) |

**Как добавить ошибку с планшета в тесты.** Владелец нажимает на ответ → «Неверно…»; отчёт `math-report-*.json` кладётся в ресурсы, и `MathReportTest` держит его исправленным. Страницы целиком — в `RealPageTest` и `RealPagesTest`.

## Данные и лицензии

- **CROHME:** только для исследований, без коммерческого использования. Скачивается в CI и `build/`, в репозитории его нет. В тестовых ресурсах — только имена формул и что ML Kit прочёл по их штрихам (`replay-reads.tsv.gz`), не сами штрихи.
- **MathWriting:** CC BY-NC-SA 4.0, пока не подключён.
- В APK ничего из этих данных не идёт (решение 14.11). Своя модель символов — только на образцах пользователя или разрешённых данных.
