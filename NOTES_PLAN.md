# План: приложение для рукописных конспектов на Android-планшете

> Исходный план от 3 ноября 2026: вопросы в нём уже решены. Что сделано — в README (список версий) и в «Справке» приложения. Оставшиеся пункты (ИИ-конспект, WebDAV, рост холста влево и вверх, замер скорости) — необязательные расширения.

## 1. Какое приложение берём за образец

| Приложение | Сильные стороны | Минусы для нас |
|---|---|---|
| **Goodnotes** | Эталон жанра: тетради с шаблонами страниц, аннотирование PDF, поиск по рукописному тексту, распознавание фигур, «обвести, чтобы выделить», AI-поиск и проверка орфографии на устройстве | Главная платформа — iPad |
| **Samsung Notes** | Лучшее нативное решение на Android: задержка около 6 мс, распознавание почерка, PDF, запись голоса | Работает только на Galaxy |
| **Nebo** | Лучшее преобразование почерка в текст, «живые» документы | Платная, своя логика страниц |
| **Squid** | Векторные чернила, бесконечный зум, хорошее аннотирование PDF | Устаревший интерфейс, слабая организация заметок |
| **Noteshelf 3** | Кросс-платформенность, синхронизация с облаками | Подписка |

**Образец — Goodnotes** (модель «тетрадь → страницы», PDF, поиск по почерку, лассо, фигуры). Берём также одну идею из **Samsung Notes** (минимальная задержка пера) и одну из **Notability** (запись звука с привязкой к штрихам). Имена, иконки и шаблоны этих приложений не копируем, делаем свои.

## 2. Отличие от плана «клон Procreate»

Конспекты — это **векторные** штрихи, а не растр. Поэтому:
- Движок на C++ не нужен. Всё пишется на **Kotlin**, используя готовые библиотеки Google.
- **Jetpack Ink (`androidx.ink` 1.0, stable)** закрывает почти весь «рисовальный» слой: low-latency отрисовка (`InProgressStrokesView`), кисти (ручка, маркер, карандаш), геометрия для ластика и лассо, компактная сериализация штрихов.
- **ML Kit Digital Ink Recognition** распознаёт почерк на устройстве, без интернета; поддерживает 300+ языков, включая русский; модель весит около 20 МБ.

## 3. Архитектура

```
UI (Jetpack Compose)
  Библиотека: папки, тетради, обложки, поиск
  Редактор: тулбар, панель страниц, свойства пера
        │
Редактор страницы (Kotlin)
  InProgressStrokesView (androidx.ink) ─ «мокрый» штрих, ~4 мс
  CanvasStrokeRenderer ─ готовые штрихи, тайловый кэш в Bitmap
  Инструменты: перо, маркер, ластик, лассо, фигуры, текст, картинка
  Undo/redo: стек команд
        │
Домен
  Notebook → Page → Layer(PDF-фон | шаблон) + Strokes + Objects
  Распознавание (ML Kit) → поисковый индекс (SQLite FTS5)
        │
Хранилище
  Room (метаданные, индекс) + файлы страниц (штрихи в protobuf)
  PDF: androidx.pdf / PdfRenderer для отображения, PDFium для экспорта
```

Ключевые решения:
1. **Страница фиксированного размера (A4/Letter) + опционально бесконечный холст.** Фиксированные страницы нужны для PDF и печати, поэтому с них и начинаем.
2. **Штрих хранится как входные точки** (`StrokeInputBatch`: x, y, давление, наклон, время) + id кисти. Так он компактен, его можно перерисовать в любом масштабе и сменить ему цвет.
3. **Ластик двух типов:** по штрихам (удаляет штрих целиком, через hit-test) и частичный (разрезает штрих по геометрии `PartitionedMesh`).
4. **Распознавание в фоне** (WorkManager): после паузы в письме страница отправляется в ML Kit, текст попадает в FTS-индекс. Поиск подсвечивает найденные слова на странице по bounding box.
5. **Только локально и офлайн на старте.** Синхронизацию закладываем в модель (UUID, `updatedAt`, журнал изменений), а реализуем позже.

## 4. Функции по приоритету

**MVP (без этого приложением пользоваться нельзя):**
- Библиотека: папки, тетради, создание, переименование, удаление, обложки.
- Шаблоны страниц: чистая, линейка, клетка, точки, поля Корнелла.
- Перо (3 типа кисти, цвета, толщина, чувствительность к давлению), маркер (рисуется под текстом), ластик двух типов.
- Palm rejection: пальцами только скролл и зум, рисует только стилус. Кнопка S Pen переключает на ластик.
- Undo/redo (жест двумя пальцами по экрану + кнопки), зум, вертикальная прокрутка страниц.
- Лассо: выделить, переместить, масштабировать, перекрасить, копировать, удалить.
- Импорт PDF и рукописные пометки поверх него; экспорт тетради в PDF.
- Автосохранение.

**v1.0:**
- Поиск по рукописному тексту (ML Kit + FTS5) и по тексту PDF.
- Распознавание фигур: удержать перо в конце штриха → линия, стрелка, прямоугольник, эллипс, треугольник.
- Жесты: зачеркнуть штрихи, чтобы стереть; обвести, чтобы выделить.
- Текстовые блоки, вставка изображений и скриншотов.
- Конвертация выделенного почерка в печатный текст.
- Панель миниатюр страниц: перестановка, дублирование, удаление.
- Закладки и оглавление тетради.

**v1.x:**
- Запись звука с привязкой к штрихам: тап по слову проигрывает момент лекции.
- Режим разделённого экрана (две тетради или PDF + конспект).
- Бесконечный холст.
- Синхронизация (свой бэкенд или Google Drive / WebDAV).
- AI-функции: резюме конспекта, карточки для повторения (по желанию, через API LLM).

## 5. Структура проекта

```
app/
  ui/library/      список тетрадей, поиск
  ui/editor/       экран редактора, тулбары
  ink/             обёртки над androidx.ink, инструменты, лассо, фигуры
  pdf/             импорт, рендер страниц, экспорт
  recognition/     ML Kit, индексатор
  data/            Room, DAO, файловое хранилище, protobuf-схемы
  domain/          модели Notebook/Page/Stroke, команды undo
```

Стек: Kotlin, Compose, Coroutines/Flow, Hilt, Room, Protobuf (lite), androidx.ink, ML Kit Digital Ink, androidx.pdf, PDFium (экспорт). minSdk 29 (Android 10).

## 5a. Целевое устройство: Xiaomi Pad 6S Pro 12.4 + Xiaomi Focus Pen

| Параметр | Значение | Что это значит для приложения |
|---|---|---|
| SoC | Snapdragon 8 Gen 2 (Adreno 740) | Производительности с запасом; оптимизировать под слабое железо на старте не нужно |
| Экран | 12,4", 3048×2032, 3:2, до 144 Гц | Страница A4 в портретной ориентации занимает почти весь экран; в альбомной помещаются две страницы. Анимации и прокрутка должны держать 144 fps |
| ОС | HyperOS (Android 14 → 15) | minSdk 29 подходит; целимся в targetSdk 35 |
| Перо | Focus Pen: 8192 уровня давления, опрос 240 Гц, заявленная задержка 3 мс, кнопки по Bluetooth | `getHistorical*` обязателен: на один кадр 144 Гц приходится 1–2 точки пера |
| Наклон | По отзывам срабатывает нестабильно | Кисти не должны зависеть от наклона; только давление и скорость |
| Кнопки пера | Сторонние приложения могут их не получать; на HyperOS 2+ кнопка-«фонарик» работает в Goodnotes/Concepts | Проверить на этапе 0, как приходят кнопки: `MotionEvent.buttonState`, `KeyEvent` (Page Up/Down?) или вообще никак. Если никак — переключатель ластика на экране и жест |

**Подготовка планшета к разработке:** в HyperOS нужно включить режим разработчика (7 тапов по «Версия ОС»), затем «Отладка по USB» и «Установка через USB». Для последнего нужна SIM-карта и вход в Mi-аккаунт. Можно отлаживать по Wi-Fi (`adb pair`).

## 5b. Результаты зонда: Huawei MatePad 10.4 (BAH4-W09) + M-Pencil

Проверено 2026-10-09: EMUI 12, Android 10, экран 2000×1200, только 60 Гц. Сырой лог: `inknotes/docs/probe-logs/huawei-bah4-w09-m-pencil.txt`.

| Что | Результат | Решение для приложения |
|---|---|---|
| Давление | 0,005…0,9995, нормировано | Используем напрямую. У пальца «давление» доходит до 18 — это мусор, для пальца его игнорируем |
| Наклон | Работает, до 67°, в том числе при наведении | Можно делать карандаш с растушёвкой при наклоне |
| Поворот пера (orientation) | Работает | Пригодится для каллиграфического пера |
| Наведение (hover) | Есть ENTER/MOVE/EXIT, но AXIS_DISTANCE всегда 0 | Показываем курсор-превью кисти; высоту над экраном не используем |
| Частота | ~214 точек/с, ~107 событий/с (unbuffered dispatch), 60 кадров/с | `getHistorical*` обязателен |
| Кнопка пера / двойной тап | Не через `buttonState`. Приходит `KeyEvent` keycode **718** (scan 190) от отдельного Bluetooth-устройства «M-Pencil» | Делаем настройку «назначить кнопку пера» с режимом обучения: нажмите кнопку — запомним keycode и устройство. Подойдёт и для Xiaomi |
| Ладонь | Касания ладони приходят как FINGER (touchMajor ~200). Когда перо подносится к экрану, система сама присылает `ACTION_CANCEL` без устройства. Ни один из 49 штрихов не прервался | Правило «рисует только стилус» достаточно; `ACTION_CANCEL` без устройства обрабатывать штатно |
| Задержки | При первом штрихе после запуска главный поток стоял ~0,2–0,25 с (до 51 точки в одной пачке). Потом изредка ~50 мс | Прогревать androidx.ink при открытии редактора (невидимый штрих). Проверить на release-сборке с R8 |

## 7. Тестирование
- Unit-тесты домена: модель, команды undo, сериализация, миграции Room.
- Скриншот-тесты страницы (Roborazzi/Paparazzi): шаблоны, рендер штрихов, экспорт PDF.
- Ручная проверка на реальном планшете: задержка, palm rejection, кнопка пера.
- Нагрузочный тест: тетрадь на 300 страниц, PDF на 500 страниц. Цель — открытие меньше 1 с и плавная прокрутка.

## 8. Риски
| Риск | Что делаем |
|---|---|
| Тормоза на страницах с тысячами штрихов | Кэш готовых штрихов в Bitmap-тайлы, перерисовка только изменённой области |
| Большие PDF | Рендер страниц лениво, по видимости, с LRU-кэшем |
| Качество распознавания русского почерка | Проверить ML Kit на этапе 0; если не устроит, рассмотреть альтернативы (MyScript SDK — платный) |
| HyperOS не отдаёт кнопки пера сторонним приложениям | Экранный переключатель «перо/ластик», жест зачёркивания для стирания |
| HyperOS агрессивно убивает фоновые процессы | Сохранять на `onPause`, индексацию через WorkManager с повторами |
| Потеря данных | Атомарная запись (temp file + rename), автосохранение, экспорт резервной копии |
